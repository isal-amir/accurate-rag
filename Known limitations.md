Terdapat beberapa kelemahan yang merupakan trade-off dengan kelebihannya:

1. Metode parsing halaman secara penuh menggunakan multimodal llm gemini (vision) yang mana boros token namun akurat dalam mengambil informasi.
2. Metode chunking dilakukan dengan cara recursive per 1000 token dalam satu halaman dengan overlap 200. Dibuat singkat agar llm lebih fokus dan minim noise informasi. Hal ini memunculkan kelemahan ketika halaman memuat tabel panjang (multi-page) maka akan terpotong.
3. Parsing dan chunking per halaman juga memnberikan kelebihan yaitu kemudahan dalam mengembalikan referensi halaman sumber jawaban sehingga user lebih mudah cross-check.
4. Streamlit menyimpan seluruh riwayat percakapan di memori statenya dan tidak disimpan di db terpisah ataupun vectorstore. Sehingga jika aplikasi direstart maka riwayat eprcakapan sebelumnya akan hilang. Metode ini juga kurang modular, ketika kita mengubah ke platform lain selain streamlit maka akan butuh banyak perubahan. Namun menurut saya untuk kasus support agent yang bukan asisten pribadi (seperti: chatGPT) tidak masalah karena riwayat percakapan tidak akan terlalu panjang, dan tiap session kemungkinan akan berbeda topik. ketika user sudah selesai dengan kendalanya maka chat lampau tidak akan lagi digunakan. 
5. Model yang digunakan merupakan free model dari OpenRouter yang mana proses invoke akan relatif lambat dan akurasi dimungkinkan di bawah performa model premium berbayar.
